# Adaptive ONZKO orchestration

This is a working method, not permission to mutate production. Always-active AGENTS.md controls apply
whether or not this Skill is selected. The parent remains accountable for integration and verification.

## Decide the smallest useful team
First identify objective, acceptance criteria, environment, gate, uncertainty and cost of error.
Small or sequential work stays parent-only. File count alone is not a reason to delegate.
Use a child only for a genuinely independent investigation, bounded implementation or useful review.
Prefer 0-2 children; the concurrent ceiling is 3. No recursive spawning, fixed pipelines, or repeated
waves to evade the ceiling. For a blocked agent, inspect the evidence before another attempt.
Do not repeat the child's investigation while waiting unless independent verification is needed.

## Brief and ownership
Read references/delegation-brief.md when delegating. Give objective, allowed paths, stable base,
environment, constraints, acceptance checks and a stopping condition. Include only necessary context.
Use named roles whose actual TOML settings match the job. Report unavailable roles/models honestly.
Complex implementation can stay with the Sol parent. There is no obligation to push it to a cheaper child.
Only one writer holds a working tree, including the parent, worker and tester. Do not review a moving diff.
Parallel read work must use stable inputs. Hand off file ownership explicitly before testing/editing.

## Conditional specialists
Explorer maps relevant code. Worker implements a bounded patch. Tester independently reproduces/checks
behaviour. Researcher verifies version-specific facts with already-approved sources/tools.
Reviewer checks a stable diff. Security and architect are optional for the corresponding consequence.
Read references/domain-controls.md for the actual domain. Keep high-consequence analysis with the
stronger configured role from the outset; do not waste a cheap attempt as a ritual.
For exceptional complexity, prepare an escalation brief and stop for Quang's premium-use approval.
Do not switch the parent or child to xhigh/max/ultra as a blind retry. Ultra may delegate automatically,
so it is not used inside this controlled explicit-subagent workflow.

## Integrate and verify
Inspect the final diff, reconcile child findings and run only authorised local checks. Material review
must be independent and risk-proportionate. A separate fresh read-only review session is preferred
when effective child permissions cannot be established. No AI review substitutes for human approval.
Do not deploy or open gates after a successful local test. Return outcome, changes, actual check results,
remaining risks/holds and next action. Name only agents that were actually spawned.

## Cost evidence
Use the pack's read-only usage analyser only after local privacy review and task completion.
Measure whole sessions, including parent/reviewer overhead. Report observed token buckets and data gaps;
never convert them to plan credits, dollars or savings without independently verified billing evidence.
