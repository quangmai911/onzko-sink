# ONZKO domain checks
Supplement to always-active controls; not a duplicate operational register.
Resolve current authority through canonical sources before implementation. This reference does not
assert that any historic hold is still open or has been closed.

## Cloudflare / Sink
Inspect manifests, lockfiles, bindings and workflows. Separate local, staging and production data.
No deploy, routes/DNS, D1 migration, KV/R2 mutation, paid resource creation or Access changes under a
local coding brief. Verify authentication and recovery before any separately approved public release.
A build passing says nothing about an exposed administrative endpoint.

## n8n / PBOS / FlowMattic
Use redacted exports and synthetic events. Check retries, idempotency, duplicate delivery, error paths
and workflow ownership. No live activation, credential export, server restart or SSH under this pack.
PBOS Stage 1 is Observe / Recommend; local development does not authorise business write-back.
Do not introduce duplicate live triggers or silently migrate a WordPress-local workflow into n8n.

## WordPress / WooCommerce
Keep the approved platform, including WoodMart/Gutenberg for Shop unless a controlled change says otherwise.
Do not edit vendor/parent-theme files or mutate live products, prices, stock, checkout or publication.
Preserve SKU identity. Use approved custom-plugin/child-theme patterns. Check capabilities, nonces where
applicable, validation, escaping, safe SQL and rollback. Owned licences are not proof of compatibility.

## Data / recovery
Schema, RLS, auth and application-data work requires its own scope and gate. Use synthetic local data.
Do not infer deployment authority for Supabase/TradeOS from a design approval. Preserve the commissioned
infrastructure unless a material approved reason supports a change. Configuration is not restore proof.

## Control ownership
Code/config-as-code: controlled repos/GitHub. Documents: Drive/REG-001. Portfolio index: MOC.
Business records stay in their domain system. n8n, Hermes and Codex must not become a shadow database.
